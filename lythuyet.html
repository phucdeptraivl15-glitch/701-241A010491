PHẦN 1: LÝ THUYẾT (40 Điểm)

Câu 1 (10 điểm): `position: relative` vs `position: absolute`

1. So sánh sự khác biệt:

  • position: relative: Phần tử giữ nguyên vị trí ban đầu trong luồng tài liệu (normal flow). Các thuộc tính top, right, bottom, left dịch chuyển phần tử so với vị trí gốc của nó. Không ảnh hưởng đến vị trí các phần tử xung quanh.
  • position: absolute: Phần tử bị tách hoàn toàn khỏi luồng tài liệu (không chiếm khoảng trống). Nó định vị dựa trên phần tử cha gần nhất có position khác static (thường là cha có position: relative). Nếu không có cha hợp lệ, nó định vị theo khung nhìn viewport / html.

2. Ví dụ tình huống Layout Responsive:

Tạo một Product Card có badge "Giảm giá 20%" ở góc trên bên phải:

/* Container giữ khung thẻ sản phẩm */
.product-card {
  position: relative; /* Làm gốc tọa độ */
  width: 100%;
  max-width: 300px;
}
/* Badge neo vào góc trên bên phải của Product Card */
.badge-sale {
  position: absolute;
  top: 10px;
  right: 10px;
  background: red;
  color: white;
}

3. Ảnh hưởng khi Deploy lên Hosting & Đa thiết bị:

Nhiều màn hình khác nhau (Desktop, Mobile, Tablet) sẽ thay đổi kích thước khung nhìn. Nếu lạm dụng absolute cứng với Pixel (vd: left: 500px), giao diện sẽ bị vỡ layout trên màn hình nhỏ. Khi deploy hosting thương mại, việc responsive sử dụng relative kết hợp Flexbox/Grid giúp các phần tử co giãn chuẩn xác trên mọi thiết bị.

Câu 2 (10 điểm): Đăng ký Domain, Cấu hình Hosting & Bảo mật

1. Quy trình đăng ký Domain & Cấu hình Hosting:

  1. Đăng ký Domain: Mua tên miền tại Nhà cung cấp (Cloudflare, Namecheap, PA Việt Nam...) và nhận quyền quản lý bản ghi DNS.
  2. Thuê/Khởi tạo Hosting: Cấu hình web server (Nginx/Apache hoặc CDN static hosting) để lưu trữ tài nguyên HTML, CSS, JS.
  3. Cấu hình DNS: Trỏ bản ghi A Record (về IP server hosting) hoặc CNAME Record (về domain của hosting platform như GitHub Pages/Netlify).

2. Vai trò của DNS:

DNS (Domain Name System) đóng vai trò như "danh bạ Internet", dịch chuyển tên miền thân thiện người dùng (vd: myapp.com) thành địa chỉ IP máy chủ (vd: 192.0.2.1) để trình duyệt tìm đúng nơi chứa mã nguồn JavaScript/HTML.

3. Hai công cụ hỗ trợ Deploy Free (No-Server):

  • GitHub Pages: Deploy trực tiếp từ repository trên GitHub, tự động hóa bằng CI/CD, hỗ trợ HTTPS miễn phí và Custom Domain.
  • Netlify / Vercel: Tự động deploy khi push code, tích hợp sẵn SSL, Serverless Functions, CDN toàn cầu tối ưu tốc độ.

4. Rủi ro bảo mật nếu cấu hình sai:

  • Chưa bật HTTPS (SSL/TLS): Dữ liệu truyền tải dạng plaintext, dễ bị tấn công Man-in-the-Middle (MITM) đánh cắp Cookie, Token.
  • Cấu hình CORS (Cross-Origin Resource Sharing) quá dễ dãi (Access-Control-Allow-Origin: *) khiến trang web dễ bị khai thác thông qua tấn công Cross-Site Scripting (XSS).

Câu 3 (10 điểm): `var`, `let`, `const` - Scope, Hoisting & Debug

1. Bảng so sánh:

Đặc tính var let const
Scope Function Scope / Global Scope Block Scope { } Block Scope { }
Hoisting Có (khởi tạo giá trị undefined) Có (nằm trong Temporal Dead Zone - TDZ) Có (nằm trong Temporal Dead Zone - TDZ)
Gán lại Được phép Được phép Không (báo lỗi TypeError)

2. Ví dụ Lỗi thường gặp (Rò rỉ biến trong vòng lặp Async):

// LỖI: Dùng var trong vòng lặp bất đồng bộ
for (var i = 1; i <= 3; i++) {
  setTimeout(() => {
    console.log("i = " + i); // In ra: i = 4, i = 4, i = 4
  }, 1000);
}

// SỬA LỖI: Dùng let để tạo block scope riêng cho từng lần lặp
for (let j = 1; j <= 3; j++) {
  setTimeout(() => {
    console.log("j = " + j); // In ra: j = 1, j = 2, j = 3
  }, 1000);
}

3. Cách Debug bằng Chrome DevTools:

  1. Mở DevTools (Phím F12 hoặc Ctrl + Shift + I) → Chuyển sang thẻ Sources.
  2. Tìm đến file script.js, click vào dòng mã chứa vòng lặp để đặt Breakpoint.
  3. Tải lại trang, dùng phím F10 (Step over) hoặc F11 (Step into) để theo dõi biến i thay đổi trong tab Scope / Watch.
  4. Dùng tab Console gõ trực tiếp tên biến để kiểm tra giá trị thực tế runtime.
